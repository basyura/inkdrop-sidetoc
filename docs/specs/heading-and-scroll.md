# 見出し解析とスクロール連動

## 見出しの抽出

Markdown 本文を改行単位で走査し、次の条件を満たす行を見出しとして抽出する。

- 行頭が 1 個以上の `#` で始まる。
- `#` の直後に 1 個以上の空白がある。
- 空白の後に 1 文字以上の非空白文字がある。

行頭に空白がある見出し、末尾に文字を持たない見出し、Setext 形式の見出しは
抽出しない。見出し文字列は、先頭の `#` 群とそれに続く空白を除いた全文とする。
末尾の `#` は除去しない。

## フェンスコードブロック

0 個以上の空白に続く 3 個のバッククォートで始まる行をフェンス境界として扱う。
開始境界から次の境界までの行は見出し抽出の対象外とする。

チルダによるフェンス、バッククォート数の厳密な対応、フェンス種別の入れ子は
判定しない。

## 見出しの範囲

各見出しの開始行は、その見出し自身の 0 始まり行番号とする。
終了行は次の見出しの直前とし、最後の見出しは文書の最終行までとする。
見出しレベルに関係なく、次に現れる見出しを範囲の境界とする。

## 編集モードの現在見出し

- カーソル移動時は、カーソル行を含む見出し範囲を現在見出しとする。
- エディターのスクロール時は、表示領域上端付近の行を基準に現在見出しを決定する。
- 表示行の算出には `editor.cursorScrollMargin` を加味する。
- 最初の見出しより前では、現在見出しを設定しない。
- 強調表示の更新時は、対応する目次項目まで SideTOC ペインをスクロールする。

## プレビューモードの現在見出し

プレビュー DOM 内の `h1` から `h6` を文書順に取得する。スクロール領域上端から
50 px 未満の位置にある最後の見出しを現在見出しとする。

強調対象の照合には、先頭から現在位置までの見出し文字列を連結し、空白を除いた
キーを使用する。同じ見出し名が複数存在する場合も、先頭からの経路で区別する。

プレビューの現在見出しが変わると、対応する Markdown 見出し行へエディターの
選択位置も移動する。この移動ではエディターの自動スクロールを要求しない。

## 前後移動

### 編集モード

- 次へ移動する場合、現在見出しの次の見出しへ移動する。
- 最初の見出しより前にいる場合、次へ移動すると最初の見出しへ移動する。
- 最後の見出しでは、次へ移動しても位置を変更しない。
- 前へ移動する場合、見出し範囲内の本文にいると現在見出しの行へ移動する。
- 現在見出しの行にいる場合は、1 つ前の見出しへ移動する。
- 最初の見出しでは、その見出し行へ移動する。

### プレビューモード

プレビュー内の見出し要素の画面位置を基準に、前後の要素へスクロールする。
ノートのメタデータ領域が表示されている場合は、文書先頭と最初の見出しの間も
移動対象として扱う。

## 内容変更の反映

- エディター更新の検出後、200 ms のデバウンスを行う。
- 現在行が `#` で始まる場合は目次を再解析する。
- 見出し以外の行では、文書の行数が変化した場合に再解析する。
- 行数が変わらない通常本文の編集では、目次を再解析しない。
- スクロール追従は約 16 ms 単位でスロットリングする。

## キャッシュ

解析結果は本文全体から算出した 32-bit 数値ハッシュをキーに最大 10 件保持する。
本文の長さにかかわらず、すべての文字を使用してハッシュを算出する。
異なる本文でも数値ハッシュが衝突し、更新を検出できない可能性はある。
