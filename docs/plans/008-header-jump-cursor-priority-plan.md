# 見出しジャンプ後のカーソル行優先修正

## 目的

Inkdrop のエディターモードで `sidetoc:jump-next` または
`sidetoc:jump-prev` を実行したとき、カーソル行から決定した sidetoc の
アクティブ見出しが、直後のスクロールイベントで上書きされないようにする。

## 背景

Vim プラグインのノーマルモードで `Ctrl+N` を連続入力して最終見出しへ移動すると、
カーソルは最終見出しにある一方、sidetoc では表示範囲上部に対応する見出しが
アクティブになることを確認した。

カーソル移動時にはカーソル行から正しく見出しを更新しているが、直後に発生する
スクロールイベントが表示範囲上部の行から再度更新し、正しい状態を上書きしている。
最終見出しの下に本文が続くノートでは、カーソルが最終見出しへ移動しても
スクロール位置は文書最下部にならない。そのため、文書最下部だけを特別扱いする
方法では解消できないことを実機で確認した。

CodeMirror 5 向けの旧実装では、カーソル移動後 100ms 以内のスクロール更新を
抑止し、カーソル行から決定した見出しを優先していた。今回はこの考え方を
`sidetoc:jump-next` / `sidetoc:jump-prev` に限定して適用する。

## 修正方針

1. 見出しジャンプを最後に実行した時刻を保持する。
   - `sidetoc:jump-next` / `sidetoc:jump-prev` で実際に見出しへ移動する直前に、
     `performance.now()` の値を保存する。
   - キーを押し続けた場合は、ジャンプごとに時刻を更新する。

2. 見出しジャンプ直後のスクロール更新を抑止する。
   - ジャンプから 100ms 以内のスクロールイベントでは `updateSection` を呼ばない。
   - カーソル行による更新は `moveEditorToLine` ですでに完了しているため、
     再計算は行わず、その結果を維持する。
   - 100ms 経過後は従来どおり表示範囲上部の行を使用する。

3. `setTimeout`、DOM 座標計算、追加のイベントリスナーは使用しない。
   - スクロールごとに時刻を 1 回比較するだけとする。
   - 既存のスロットリングを維持する。

4. 通常のカーソル移動、手動スクロール、sidetoc の見出しクリック、
   プレビュー表示の見出し同期処理は変更しない。

## 編集対象

- `src/sidetoc-pane.tsx`
- `lib/sidetoc-pane.js`（ビルドで生成）

## 検証項目

- `npm run build` が成功すること。
- 「現状把握 - 2026.07.11」で `Ctrl+N` を連続入力し、最終見出し
  「改善したと判断できる状態」と sidetoc のアクティブ表示が一致すること。
- `Ctrl+P` で上方向へ移動した場合も、カーソル位置とアクティブ表示が一致すること。
- コマンド実行から 100ms 経過後に本文を手動スクロールすると、表示位置に応じて
  sidetoc のアクティブ表示が更新されること。
- sidetoc の見出しクリックによる移動が変わっていないこと。
- プレビュー表示のスクロール連動が変わっていないこと。
- タイマー、DOM 座標計算、追加のイベントリスナーが増えていないこと。
- `git diff --check` で問題がないこと。

## 実施結果

- `moveEditorToLine` にカーソル行を優先する指定を追加し、
  `sidetoc:jump-next` / `sidetoc:jump-prev` からの移動だけで有効にした。
- 見出しジャンプから 100ms 以内のエディタースクロール更新を抑止した。
- `setTimeout`、DOM 座標計算、追加のイベントリスナーは使用していない。
- `npm run build` 成功。
- `git diff --check` 問題なし。
- 「現状把握 - 2026.07.11」で `Ctrl+N` を連続入力し、最終見出しと
  sidetoc のアクティブ表示が一致することを確認した。
- 最終見出しから `Ctrl+P` を実行し、一つ前の見出しと sidetoc の
  アクティブ表示が一致することを確認した。
